The GNOST Folder
================

Everything GNOST writes goes into one folder in your project, ``.gnost/`` (change it with
``output_dir`` in ``.gnost.toml``). It is meant to be read by people, tools and coding agents, so
its layout and its JSON are treated as an interface.

.. list-table::
   :header-rows: 1
   :widths: 30 70

   * - Path
     - What it is
   * - ``README.md``
     - Explains the folder to anyone who finds it, and how to regenerate it.
   * - ``ONBOARD.md``
     - The onboarding guide: entry points, flow, routes, change hotspots, risky and changing files.
   * - ``insights.json``
     - The same facts as data. Has a ``schema_version`` and a JSON Schema (``gnost/schemas/insights.schema.json``).
   * - ``flow/``
     - Mermaid diagrams (``.mmd``) and Markdown pages that GitHub renders.
   * - ``flow.html``
     - The interactive explorer, one page that works offline (``gnost open flow``). Not committed.
   * - ``analysis/``
     - ``analysis.json``, ``analysis.html`` and ``analysis.sarif`` from ``gnost analyze -o --sarif``.
   * - ``changes/``
     - ``changes.md`` and ``changes.json`` from ``gnost changes``.
   * - ``baseline.json``
     - Known findings, so CI reports only new ones (see :doc:`ci`).
   * - ``badge.svg``
     - The final score as a README badge, from ``gnost analyze --badge`` (see :doc:`scoring`).
   * - ``.gitignore``
     - Ignores ``*.html``: those pages are large and can be rebuilt.

Commit it
---------

The folder is safe to commit. Every file except the ``.html`` pages is plain text and changes only when your
code does, so a pull request that moves the architecture shows up in the diff. Rebuild it with
``gnost onboard .`` (or ``npx gnost-cli onboard .``). Every Markdown file ends with a "Generated by GNOST"
line; switch it off with ``footer = false`` in ``.gnost.toml``.

What stays stable
-----------------

* The file names above and the folder name (unless you set ``output_dir``).
* ``insights.json``: new fields may be added at any time (``schema_version`` goes up by a minor number),
  but a field is never renamed or removed without a new major ``schema_version``. Read the version, ignore
  fields you do not know.
* ``changes.json`` has its own ``schema_version`` and follows the same rule.
* GNOST never deletes files it did not write. Old output from before 0.6.0 (``ONBOARD.md`` at the root and
  ``docs/flow``) is read as a fallback and is safe to delete.

For coding agents
-----------------

``gnost init --agents`` writes an ``AGENTS.md`` that tells coding agents to read ``.gnost/ONBOARD.md`` and
``.gnost/insights.json`` before they search the tree, and to run ``gnost changes origin/main`` before a
change. An existing ``AGENTS.md`` is never overwritten unless you pass ``--force``.

What is in ``insights.json``
----------------------------

``project`` (name, languages), ``entry_points``, ``routes``, ``layers`` (entry, core, leaf), ``first_files``,
``hotspots``, ``caution_areas`` (fragile files with their scores), ``cycles``, ``graph`` (files and imports),
``stats``, ``quickstart`` (install, build, run and test steps read from the project's own files), ``flows`` and ``callgraph`` (function level, Python), ``change_history`` (git history of each file)
and ``risk`` (fragile and changing files). Paths are relative to the scanned folder.
