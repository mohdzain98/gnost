Configuration
=============

GNOST works without any configuration. To change its defaults for a project, add a
``.gnost.toml`` file at the root of the repository (GNOST looks for it from the folder
you scan upwards, and stops at the repository root).

Order of precedence: **command-line flags**, then ``.gnost.toml``, then the built-in
defaults. Unknown settings are reported as warnings and ignored; a setting with the
wrong type stops the command with a message that names the file and the setting.

Create the file with ``gnost init``
-----------------------------------

You do not need to copy settings from this page. ``gnost init`` writes a complete
``.gnost.toml`` at the root of the repository, with every setting at its default value and a
short comment on each, so you can edit what you need and leave the rest:

.. code-block:: bash

   gnost init            # write .gnost.toml (refuses to overwrite; add --force to)
   gnost init --print    # show the defaults without writing anything

``gnost init`` can also wire GNOST into the project (each is a small edit that keeps your
comments and formatting, does nothing if it is already set up, and shows what it changed;
``--dry-run`` shows it without writing):

.. code-block:: bash

   gnost init --pom             # add gnost-maven-plugin to pom.xml
   gnost init --npm             # add a "gnost" script to package.json
   gnost init --github-action   # write .github/workflows/gnost.yml (runs the GNOST action)
   gnost init --agents          # write AGENTS.md that points coding agents to .gnost/

A complete example
------------------

.. code-block:: toml

   # Files and folders skipped by onboard and analyze.
   # A name matches a folder anywhere, a pattern matches file names or paths.
   exclude = ["legacy", "*.generated.ts", "docs/build"]

   # The folder GNOST writes its files to, inside the project (default ".gnost").
   output_dir = ".gnost"

   # Say so when a newer gnost exists (default true; see "Update notice" below).
   check_updates = true

   # End the Markdown files GNOST writes with a "Generated by GNOST" line (default true).
   footer = true

   [onboard]
   max_edges = 150      # largest diagram drawn file by file (default 200)
   collapse = 1         # always group diagrams by folder
   depth = 3            # limit how deep the execution flow goes

   [caution]            # which files are "risky to change"
   threshold = 50       # lowest caution score reported, 0-100 (default 40)
   limit = 15           # most files reported (default 10)

   [caution.weights]    # the most each signal can add to a score, 0-1
   size = 0.5

   [caution.ranges]     # [value that counts as 0, value that counts as 1]
   size = [300, 1500]   # lines of code

   [risk]               # files that are fragile AND changing (needs git history)
   threshold = 30

   [history]            # change hotspots (needs git history)
   days = 180
   exclude_authors = ["*[bot]", "ci-*"]

   [analyze]
   analyzers = ["maintainability", "readability"]
   fail_under = 7.5     # CI: exit code 3 when the final score (0-10) is lower
   baseline = ".gnost/baseline.json"   # report only findings not in this file
   timeout = 600
   max_findings = 500
   parallel = true

Change hotspots
---------------

The ``[history]`` section controls the "Change Hotspots" table that ``gnost onboard`` adds when it can read
git history (see :doc:`onboard`). All keys are optional:

.. code-block:: toml

   [history]
   enabled = true
   days = 365            # how far back to look
   max_commits = 5000    # most commits read
   recent_days = 90      # what counts as "recent"
   min_commits = 2       # a file needs this many changes to be listed
   top = 15              # most files listed in ONBOARD.md
   max_files_per_commit = 150   # bigger commits (mass reformat, vendoring) are ignored
   exclude_authors = ["*[bot]", "dependabot*", "renovate*"]   # patterns; case does not matter

Risk
----

The ``[risk]`` section controls the "Risky and Changing" table (see :doc:`onboard`), which combines the
caution score with the change history. All keys are optional:

.. code-block:: toml

   [risk]
   threshold = 20      # lowest risk listed, 0-100
   limit = 10          # most files listed
   churn_weight = 1    # 1: risk = caution score x change activity; 0: ignore change activity

Caution score
-------------

``gnost onboard`` ranks files by how risky they are to change and lists the worst under
"Caution Areas". Each file gets a score from 0 to 100 built from these signals:

=============  ========================================================  ===============
Signal         Meaning                                                   Default weight
=============  ========================================================  ===============
cycles         part of a circular dependency (deferred ones count less)  0.9
impact         how many files import it                                  0.8
size           lines of code                                             0.7
complexity     most complex function (Python) or branch count estimate   0.7
coupling       how many project files it imports                         0.5
observability  ``except`` blocks that neither log nor re-raise (Python)  0.4
=============  ========================================================  ===============

Signals combine like independent risks: one strong signal is enough to flag a file and
several moderate ones add up. Signals that cannot be measured for a language (complexity
estimates for JS/TS/Java, observability outside Python) are left out and the score is
marked *partial*. Generated files (in a ``generated`` folder or with a "generated" header)
are never listed.

Each entry in the insights JSON includes the score and the ``factors`` behind it, so
scripts can see why a file was flagged.

Update notice
-------------

``gnost --version`` (and ``gnost version``) checks once a day whether a newer release exists and,
if so, adds one line on stderr: ``A new version of gnost is available: 0.7.0 (you have 0.6.0)`` with
the command to upgrade. It is built to never get in the way:

- It runs only when you are at a terminal. In scripts, pipes and CI it does nothing, so
  ``$(gnost version)`` is always exactly ``gnost 0.6.0``.
- With no network, a slow connection or any error it prints nothing and does not fail. A failed
  attempt is not repeated for six hours, so being offline never slows you down.
- It makes one request to pypi.org (the package index), never to a GNOST server, and sends
  nothing about you or your project. The answer is cached in ``~/.gnost/update-check.json``.
- Switch it off with ``check_updates = false`` in ``.gnost.toml`` or ``GNOST_NO_UPDATE_CHECK=1``.
